# 从人工判断到自动打分

* 在大模型（LLM）出现之前，自然语言处理（NLP）评估的主战场聚焦于边界清晰的具体任务，如 **文本分类、实体识别、机器翻译** 等，那一代评估体系的核心目标是：**如何低成本、可重复地替代人工打分？**
* 传统指标（如 **BLEU、ROUGE、F1**）的流行，正是为了回应评测社区对 **快速复现** 和 **方便刷榜** 的需求。然而，**单纯的字符串重叠并不等于真正的语义质量**，这也为后来大模型时代评估体系的演进埋下了伏笔

# 1. 传统评估的基本逻辑

传统 NLP 指标大体可以分为三类，它们分别对应不同的任务假设和应用场景：

1. 第一类是 **判别式指标**，也就是分类和序列标注任务里最常见的 **Accuracy、Precision、Recall、F1**
2. 第二类是 **答案匹配指标**，典型代表是抽取式问答中的 **Exact Match** 和 **token-level F1**
3. 第三类是 **文本生成指标**，代表性的就是机器翻译里的 **BLEU** 和摘要里的 **ROUGE**；再往后，则发展出基于预训练表示或监督学习的语义指标，例如 **BERTScore、BLEURT 和 COMET**。它们分别对应不同的任务假设：标签空间明确，答案边界可定位，语言生成质量可以通过参考文本相似度近似描述

| **指标类型** | **核心假设** | **代表任务** | **典型指标** |
| ---------- | -------------------- | -------------- | ------------------------------- |
| **判别式指标** | 标签空间明确，非黑即白 | 文本分类、序列标注 | Accuracy、Precision、Recall、F1 |
| **答案匹配指标** | 答案边界可定位 | 抽取式问答（QA）、信息抽取 | Exact Match (EM)、Token-level F1 |
| **文本生成指标** | 生成质量可通过参考文本的相似度来近似描述 | 机器翻译、文本摘要 | BLEU、ROUGE、BERTScore |

***NLP 指标总结表***

**GLUE** 作为多任务 NLU 基准，**SQuAD** 作为阅读理解基准，**WMT** 作为机器翻译共享评测，CNN/DailyMail 与 XSum 作为摘要数据集，基本构成了这一评估时代的骨架

> 这套体系最大的优点是 **绝对的可复现性**：同样的数据和脚本，同样的指标，通常能得到高度一致的结果。但其致命弱点在于：**可计算的东西，不一定等于真正重要的东西**。例如，一段摘要如果使用了不同的同义词，即使事实完全正确，ROUGE 也可能给出低分。这套表面匹配的逻辑，并没有彻底解决“**自动评估是否真的评测了人关心的质量**”，正是大模型评测必须向语义评估和偏好评估扩展的根本原因

# 2. 分类与序列标注：Accuracy、Precision、Recall、F1

在 **文本分类、情感分析、自然语言推断、命名实体识别** 这类任务中，最直观基础的指标是 **准确率（Accuracy）**：

$\mathrm{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}$

其中 TP、TN、FP、FN 分别是真正例、真负例、假正例和假负例

**优点：** 直观

**局限性：** 当 **数据集极度不平衡时，Accuracy 会产生严重误导**。例如模型即使全部预测为多数类，也能获得极高的准确率。因此，业界引入了精确率（Precision）、召回率（Recall）以及它们的调和平均数 $F_1$：

* **Precision (精确率):** 预测为正的样本里，有多少是真的。 $\mathrm{Precision}=\frac{TP}{TP+FP}$
* **Recall (召回率):** 真实为正的样本里，有多少被找出来了。 $\mathrm{Recall}=\frac{TP}{TP+FN}$
* ** $F_1$ Score:** 二者的调和平均 $F_1=\frac{2\cdot \mathrm{Precision}\cdot \mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}$

![[_Attachments/Images/12.1 传统 NLP 评估指标-image-1.png]]

**F1 往往比 Accuracy 更有解释力，因为模型面对的不是简单分类，而是边界识别与类型判断的组合问题**。CoNLL-2003 命名实体识别共享任务之所以长期使用 F1，而不是 Accuracy，原因就在这里：命名实体识别的误差并不只是类判错，还包括 span 边界错位

**多类别任务中的微观与宏观聚合：**

* **Macro-F1:** 先计算每个类别的 $F_1$，再取平均。**对长尾/少数类非常敏感**
* **Micro-F1:** 将所有类的 TP、FP、FN 汇总后统一计算。**容易被多数类主导**

若一个模型在大类上很强、在小类上很差，micro-F1 可能仍然好看，但 macro-F1 会明显下降。因此，在类别分布不均衡、长尾严重或者安全类标签重要性不对称的场景中，macro-F1 往往更值得关注

> **注意：** 在撰写评估报告时，如果模型在长尾问题上表现糟糕，仅报告 Micro-F1 会掩盖其缺陷。严谨的做法是同时报告两者

# 3. 抽取式问答：Exact Match 与 Token-level F1

SQuAD 等经典阅读理解数据集以及抽取式问答中，完美体现了传统 NLP 指标对答案形式的高度敏感：

* **Exact Match (EM):预测答案与参考答案必须一字不差，才记为 1，否则为 0**。$\mathrm{EM}=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[\hat y_i = y_i]$
* **Token-level F1:** 计算 **预测答案与参考答案在 Token 级别的重叠来计算 Precision 和 Recall，再取调和平均**

**应用痛点：** 这个指标非常严格，优点是明确，缺点是太硬。例如参考答案是 `Barack Obama`，预测答案是 `Obama`，语义上可能只差一点，但 EM 直接记 0。**这种死记硬背式的匹配在传统抽取式任务中尚可忍受，但在开放式生成中则完全失效**

于是又引入 **token-level F1，** 给部分正确留出空间。SQuAD 之所以同时报 EM 和 F1，就是因为二者分别对应 **“严格匹配”和“内容覆盖”** 两种不同评判标准

> 这种设计后来对大模型评测仍然有启发，你会发现，很多所谓“答案正确率”的争论，其实都在重复 EM 和 F1 的老问题：**到底是要求字面完全一样，还是允许语义等价、表述不同的答案被判为正确？** 传统抽取式问答因为答案通常来自原文 span，所以这个矛盾还不算特别严重；到了开放式生成，问题就立刻放大了。也正因此，EM/F1 适合抽取式 QA，却不适合直接拿去衡量开放问答。**指标从来都不是普适的，它必须和任务形式绑定**

# 4. 机器翻译与自动摘要：BLEU vs ROUGE

BLEU 的核心思想是：**一个好的机器翻译，应该在多个尺度的 n-gram 上与参考翻译具有较高重合度，同时不能通过故意生成极短句子来钻空子**。因此 **BLEU 定义为 modified n-gram precision 的几何平均，再乘以一个 brevity penalty**：

$\mathrm{BLEU}=\mathrm{BP}\cdot\exp\sum_{n=1}^{N} w_n \log p_n$

其中 $p_n$ 是 (n)-gram 的修正精确率，$w_n$ 是权重，通常取均匀分配；$\mathrm{BP}$ 是长度惩罚项，常写为：

![[_Attachments/Images/12.1 传统 NLP 评估指标-image-2.png]]

这里 c 是候选译文长度，r是参考译文长度。之所以要有 BP，是因为 **如果没有长度惩罚，模型只输出几个高频词，也可能获得不低的 n-gram 精确率**。BLEU 的贡献，不在于它完美，而在于它第一次让机器翻译有了一个可规模化、便于共享任务比较的自动指标

**BLEU 问题：** 但 BLEU 的问题也非常明显。第一，它 **偏向表层匹配，对同义改写不友好**。第二，它 **更适合语料级评估，不太适合句子级稳定比较**。第三，它 **依赖参考翻译，而参考翻译本身可能并不唯一**

与 BLEU 相对应，在自动摘要任务中最具代表性的指标则是 **ROUGE**。如果说 BLEU 更关心 **生成的内容有多少是对的**，那么 ROUGE 更关心 **参考答案中的关键信息，有多少被生成结果覆盖到**。因此，**ROUGE 整体上更偏向 Recall 导向，也更适合摘要这种强调信息覆盖的任务**

最常见的是 **ROUGE-N**，它衡量参考摘要中的 n-gram 有多少被生成摘要命中。其定义通常写为：

$$\mathrm{ROUGE\text{-}N} =
\frac{
\sum_{g_n \in \mathrm{Ref}}
\mathrm{Count}_{\mathrm{match}}(g_n)
}{
\sum_{g_n \in \mathrm{Ref}}
\mathrm{Count}(g_n)
}$$

其中， $g_n$ 表示一个 n-gram， $\mathrm{Count}(g_n)$ 是该 n-gram 在参考文本中出现的次数， $\mathrm{Count}_{\mathrm{match}}(g_n)$ 是它同时出现在生成文本和参考文本中的匹配次数。这个公式本质上体现的是召回率

除了 ROUGE-N，实际使用中也非常常见的是 **ROUGE-L，** 它不只看固定长度的 n-gram，而是基于 **最长公共子序列** 来 **衡量两段文本在整体结构和内容顺序上的一致性**。其 precision、recall 和 F 值可以写为：

$$R_{LCS}=\frac{LCS(X,Y)}{m}, \qquad
P_{LCS}=\frac{LCS(X,Y)}{n}$$

其中，X 是参考文本，Y 是生成文本，m 和 n 分别是二者长度，LCS(X,Y) 是最长公共子序列长度。相比只看局部片段重合的 ROUGE-N，**ROUGE-L 更能反映文本整体的信息保留与句子组织情况**，因此在摘要评测中也被广泛采用

不过，ROUGE 和 BLEU 一样，本质上都还是 **字面匹配型指标**。它们 **能衡量像不像参考答案，却不一定能判断语义是否等价、事实是否正确、表达是否自然**

| **特性** | **BLEU (机器翻译)** | **ROUGE (文本摘要)** |
| -------- | ---------------------------------------- | ------------------------------------ |
| **核心机制** | 统计生成的 n-gram 有多少在参考译文中（Precision 导向） | 统计参考摘要的 n-gram 有多少被生成文本覆盖（Recall 导向） |
| **惩罚机制** | 长度惩罚项 (Brevity Penalty)，防止模型输出极短的废话来骗取高分 | 通常结合最长公共子序列 (ROUGE-L) 来评估句子结构连贯性 |
| **主要盲点** | 无法识别同义词改写，对“信、达、雅”中的“达和雅”无能为力 | 无法检验事实正确性（幻觉），容易被冗长且重复的文本欺骗 |

# 5. 从字面重叠到语义匹配：BERTScore、BLEURT 与 COMET

随着预训练语言模型（PLM）的爆发，数 n-gram 的方式显得过于原始，开始转向 **语义级评估**：

1. **BERTScore：** 利用 **预训练模型提取向量表示，计算候选文本与参考文本之间的余弦相似度**。BERTScore 的优势，是对同义表达和局部改写更宽容，因此在多种文本生成任务上与人工判断相关性更高
2. **BLEURT：** 将评估本身定义为一个监督学习问题。通过预训练加上少量的人工质量打分数据，直接训练一个回归模型来模拟人类打分
3. **COMET：** 在机器翻译中，不仅比较模型输出和参考答案，还 **显式引入 source sentence 输入**。这让 COMET 具备了判断译文是否忠实于原文的能力

尽管这些指标与人类评价的相关性远高于 BLEU，基于模型的评估指标仍然存在盲点，比如 **对某些截断错误不敏感，对篇章层面的 coherence 识别不足，或者本身带有特定语料和模型偏差**。也就是说，BERTScore、BLEURT、COMET 比 BLEU、ROUGE 更进了一步，但它们依然只是自动评估器，不是人类判断的完美替身。传统指标的问题是太表面，学习式指标的新问题则是更黑箱，也可能被诱骗

# 6. 评估指标的元评估 (Meta-Evaluation)

> **指标本身也需要被评估**

一个自动指标是否可靠，通常要看它与人工判断的相关性。我们如何证明 COMET 比 BLEU 好？答案是计算自动打分与 **人类专家打分（Human Judgement）** 的相关性。常用的有 **Pearson 相关系数、Spearman 等级相关系数和 Kendall’s $\tau$，以皮尔逊（Pearson）为例**：

$r=\frac{\sum_i (x_i-\bar x)(y_i-\bar y)} {\sqrt{\sum_i(x_i-\bar x)^2}\sqrt{\sum_i(y_i-\bar y)^2}}$

其中 $x_i$ 是自动指标得分，$y_i$ 是人工评分。相关性越高，说明该指标越接近人工判断。这里还要区分 system-level 和 segment-level：前者 **看不同系统整体平均质量的排序是否一致，后者看单句级别打分是否和人工一致**。很多指标在 system-level 很强，但到 sentence-level 就明显不稳。

这套方法论延续至今：我们 **用 LLM-as-a-judge，同样需要验证这个AI 裁判与人类偏好的对齐程度**

# 7. 总结

评估体系的演进，本质上是模型能力逼近人类智能时的必然结果

**传统指标解决了什么？**

* 将模型比较从主观感受变成了客观分数
* 催生了公开的排行榜（Leaderboard，如 GLUE），为模型迭代提供了统一的准星
* 完成了从字面匹配向语义匹配的初步跨越

**传统指标没解决什么？**

* 无法应对开放式生成的一题多解
* 无法有效区分逻辑连贯性与单纯的词汇堆砌
* 完全无法衡量模型在多轮交互、长程规划和工具调用（Agent 场景）中的真实任务完成率
