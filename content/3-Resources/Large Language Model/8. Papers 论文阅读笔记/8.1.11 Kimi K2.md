# Introduction

> * **研究背景：**
> * 大模型目前的发展方向向 **智能体智能** 转变，即 **模型本身就是智能体**，可以在 **复杂环境中动态的进行感知、规划、推理、行动**（<u>与环境</u>**<u>主动且持续的交互学习，获取数据分布外的新技能</u>**<u>，与传统强化学习智能体定义靠近，只不过感知和决策都是由大模型完成</u>）。智能体动态交互，可以通过 **自身的探索和利用能力，突破数据限制**
> * **预训练：** 通用高质量数据有限，**需要提高 token 效率**（学习信号/token）
> * **后训练：** 多步推理、长期规划和工具使用等 Agent 数据罕见，**需要构建可扩展高质量合成方法**
> * **研究内容：**
> * **MuonClip 优化器**，高效 token 利用的 Muon 算法结合 QK-Clip 稳定性增强机制
> * 引入了 **大规模 Agent 数据合成 pipeline**，通过模拟及现实环境系统地生成工具使用 demo 数据
> * 设计了 **融合可验证奖励（RLVR）与自我批判评分奖励机制的通用强化学习框架**

# Pre-training

## MuonClip 优化器

> **苏剑林苏神的讲解：**
> [**QK-Clip:让Muon在Scaleup之路上更进一步 - 科学空间|Scientific Spaces**](https://kexue.fm/archives/11126)
> [**Muon续集:为什么我们选择尝试Muon? - 科学空间|Scientific Spaces**](https://kexue.fm/archives/10739)
> [**Muon优化器赏析:从向量到矩阵的本质跨越 - 科学空间|Scientific Spaces**](https://kexue.fm/archives/10592)
> * Kimi K2 使用 **token 高效的 Muon 优化器**（<u>具体原理可以参考上面给的链接</u>），MoonLight 的研究中显示相同的训练数据量下 Muon 的性能显著优于 AdamW
> * **注意力 MaxLogits 爆炸问题：** 在对做 **softmax 之前的注意力分数 logits 随着训练一直上涨的现象**
> > 其中输入 $x$ 一般会有 RMSNorm 不会爆炸，但是 $||W_q||,||W_k||$ 就有无穷大的风险
> >
> > $S_{\max} = \max q_i \cdot k_j$
> >
> > $|q_i\cdot k_j| \leq ||q_i||||k_j|| = ||x_iW_q|||x_jW_k|||\leq||x_i||||x_j||||W_q||||W_k||$
> * **一些已有的尝试：**
> * **Weight Decay：** Muon 本身就有 Weight Decay 的设置，一定程度上可以预防小模型出现 MaxLogit 爆炸，非常大参数量的模型上会带来明显的效果损失
> * **Soft-cap 软截断：** $\text{softcap}(x,\tau)=\tau\text{tanh}(\frac{x}{\tau})$，直接截断注意力 logits，可以保证其有界，但在应用截断之前，Q K 之间的点积仍可能过度增长
> * **QK-norm：** $\bar{Q},\bar{K}=\text{RMSNorm}(Q),\text{RMSNorm}(K)$，很有效，但是不适用于 MLA，因为 MLA 在训练和推理阶段的 Q K 不一致，详 **见[[1.3 Attention 注意力]]**
> * **QK-Clip：** 权重更新后重新调整 Query 和键 Key 的投影权重，以限制注意力 logits 的增长
> 对于 Attention 的 **每一个 head 来说最大 logit 定义为 batch B 中 softmax 之前的最大输入：**
> $S_{max}^h=\frac{1}{\sqrt{d}}\max_{X∈B}\max_{i,j}Q_i^hK_j^{h⊤}$
> QK-Clip 的核心思想就是 **，当 $S_{max}^h$ 超过阈值 T 之后，就对 Q，K 的权重矩阵 $W_q,W_K$ 进行裁剪**，由于实际上 **只有一小部分 head 会出现 logits 爆炸的现象**，为了最大限度地减少对模型训练的干预，可以对所有 heads 进行 **逐 head 的 QK-clip** 如下：
> $W_{q}^{h} \leftarrow \gamma_{h}^{\alpha} W_{q}^{h} \quad W_{k}^{h} \leftarrow \gamma_{h}^{1-\alpha} W_{k}^{h}$
> 其中， $\gamma_{h} = \min(1, \tau / S^{h}_{\text{max}}) ,\ \ \alpha=0.5$
> 以上操作可以直接对 MHA 进行操作，**对 MLA 来说 QK- Clip 只作用于非共享的 head 上**
> > 这里可以回顾 MLA 部分对于ROPE的处理[[1.3 Attention 注意力]]，MLA给出的解决方案是用 **额外的多头queries和共享的key去结合RoPE**
> * $q^{C}和k^{C}$ 各自按 $\sqrt{\gamma_{h}}$ 进行缩放
> * $q^{R}$（额外的多头query）：按 $\gamma_{h}$ 进行缩放
> * $k^{R}$（额外的共享key）：保持不变，以避免对其他注意力头产生影响
>

## 预训练数据：领域专用重述实现高效 token 利用

> 通过 **领域专用重述技术（知识领域风格 / 视角多样化重述、数学领域 “学习笔记” 风格改写）提升高质量数据的利用率，减少过拟合**
> * **Token 效率：训练过程中每消耗一个 token 所能带来的性能提升程度。** 简单的提高 token 效用的方法是让模型 **反复接触相同的 token，但这可能会导致过拟合并降低泛化能力**
> * Kimi K2 主要描述了对于 **知识领域数据和数学领域数据** 的重述技术

### 知识领域数据重述
>
> 知识密集型数据上需要多轮重复训练让模型全面吸收知识，但是这样会导致 token 效率下降，过拟合风险，K2 采用以下合成数据框架：
> * **风格与视角多样化 prompt：** 一系列精心设计的提示词引导模型以不同风格和视角，生成重述内容
> * **Chunk-wise 的自回归生成：** 将文本分割成多个片段，分别进行重述，然后拼接在一起，减轻隐性输出长度限制
> * **保真度验证：** 对比每个重述段落与其来源文本的语义对齐程度，进行初始质量控制

![8.1.11 Kimi K2-image-6.png](https://2479e837.cloudflare-imgbed-2q4.pages.dev/file/1782697400590_8.1.11_Kimi_K2-image-6.png)

### 数学领域数据重述

参考 **SwallowMath（https://arxiv.org/abs/2505.02881）** 的方法，将 **高质量的数学文档重写成 “学习笔记” 风格**。其他语言的高质量数学资料翻译成英文，来增加数据的多样性

> 这一点有点像 Textbook is all you need 中提到的将数据改写为高质量的教科书案例式数据

# Post-training

## SFT：大规模工具使用智能体数据合成 pipeline

> 两个核心原则：**最大化提示多样性和确保高响应质量**
> 重点是对智能体数据设计了一套数据合成流程，大规模模拟现实世界的工具使用场景，通过多步骤的交互式推理来学习工具使用能力。主要有三个阶段：
> 1. **工具规格生成：** 首先构建一个巨大的工具仓库，包含真实世界工具和LLM合成的工具
> * 从 **GitHub 仓库中直接获取了 3000 多个真实的 MCP 工具**
> * 通过 **分层领域生成过程系统地演化出合成工具**：从核心类别（如金融交易、软件应用、机器人控制等）入手，再在每个类别中演化出多个具体的应用领域，然后为每个领域合成专用工具，这些工具具有清晰的接口、描述和操作语义，生成 **超过 20000 个合成工具**
> 2. **智能体和任务生成：** 对每个工具集生成一个使用该工具集的智能体以及一些相应的任务
> * 合成 **各种系统提示词，并为智能体配备工具库的不同工具组合**，生成了数千个智能体，形成了多样化的智能体群体，**每个智能体具备不同的能力、专业领域和行为模式，从而确保能够广泛覆盖各种潜在的使用场景**
> * **基于评分标准进行任务生成，针对每种智能体配置，生成涵盖从简单到复杂操作的各类任务。** 每个任务都配 **有明确的评分标准，其中规定了成功标准、预期的工具使用模式以及评估检查点**，确保对智能体性能的评估具有一致性和客观性
> 3. **轨迹生成：** 针对每个智能体和任务，生成智能体通过调用工具完成任务的轨迹
> * **用户模拟：** LLM 生成具有独特沟通风格和偏好的用户角色，与智能体进行多轮对话，从而构建出贴近现实的互动模式
> * **工具执行环境：** 复杂的工具模拟器（功能上等同于世界模型）执行工具调用并提供逼真的反馈。该模拟器在每次工具执行后维护并更新状态，支持具有持续影响的复杂多步骤交互。引入可控的随机性，以产生包括成功、部分失败和边缘情况在内的多种结果
> 4. **质量验证和过滤：** 使用 LLM-as-a-Judge 的方法，根据任务评分标准对每条轨迹进行评估，只有符合成功标准的轨迹才会被保留用于训练
> 5. **真实性扩展：** 对于真实性至关重要的场景（尤其是编码和软件工程任务），将模拟环境与真实沙盒相结合，执行实际代码，与真实开发环境交互，并提供真实反馈

## RL

### 可验证的 Gym 环境

1. **数学、STEM及逻辑任务**
   * **多样化覆盖**：对于 **数学和STEM任务**，结合 **专家标注、内部问答提取流程和开放数据集收集高质量问答对，并通过标签系统增加覆盖不足领域的内容**；**逻辑任务数据集** 包含结构化数据任务（如多跳表格推理、跨表聚合）和逻辑谜题（如24点游戏、数独等）
   * **中等难度**：基于SFT模型的pass@k准确率评估问题难度，**仅选择中等难度问题作为RL提示集**，以避免因过易或过难导致学习信号弱、效率低的问题
2. **复杂指令遵循**
   * **混合验证框架**：结合 **自动验证与对抗性检测，及可扩展的课程生成流程**，通过双路径系统确保精度和鲁棒性。其中，**混合规则验证包括对有可验证输出的指令通过代码解释器进行确定性评估，对需细致理解约束的指令采用LLM作为评判器评估，同时加入额外的hack-check层检测模型的欺骗性声明**
   * **多源指令生成**：采用 **三种生成策略构建训练数据**，分别是数据团队精心设计的复杂条件提示和评分标准、受 AutoIF 启发的智能体指令增强，以及专门生成用于探测特定失败模式或边缘情况的微调模型，以保证指令覆盖的广度和深度
3. **忠实性**
   * 受 FACTS Grounding 评估框架启发，**训练句子级忠实性评判模型进行自动验证**，该模型能检测出在上下文中没有支持证据却做出事实性声明的句子，并作为奖励模型提升整体忠实性表现
4. **编码与软件工程**
   * 从开源数据集和合成来源收集问题及评判标准，并融入从预训练数据中提取的高质量人工编写单元测试，确保合成数据的多样性和奖励信号的正确性
   * 针对软件工程任务，从GitHub收集大量拉取请求和问题，构建包含用户提示/问题及可执行单元测试的软件开发环境，该环境基于强大的沙盒基础设施
5. **安全性**
   * 从人类精心设计的种子提示集入手，涵盖暴力、欺诈、歧视等常见风险类别
   * 通过包含攻击模型（迭代生成旨在引发目标LLM不安全响应的对抗性提示）、目标模型（对提示做出响应以模拟潜在漏洞）和评判模型（评估交互以确定对抗性提示是否成功绕过安全机制）的自动提示进化流程，模拟复杂的越狱尝试，并使用特定任务评分标准对每个交互进行评估，由评判模型给出成功/失败的二元标签

### 自评估标准奖励

引入 **基于自评估反馈的通用强化学习框架，即模型通过评估自身输出来生成偏好信号**

通过将 **从可验证场景中习得的能力扩展到更广泛的主观任务中，** 使 LLM 与人类细微的偏好（包括有用性、创造性、推理深度、事实性和安全性等）相契合

1. **自评估策略优化**
   在学习循环的首个核心流程中，K2 作为 actor 为涵盖广泛应用场景的通用提示生成响应；随后 K2 作为 critic，结合多种评估标准对所有结果进行 pairwise 排序。这些标准包括代表 Kimi 核心价值观的核心标准、旨在消除奖励黑客行为的规定性标准，以及数据团队为特定指令场景设计的人工标注标准。尽管部分标准可设为强制性，但 K2 仍保留根据内部先验权衡的灵活性，以实现与自身不断演化的在策略行为的动态、持续对齐，确保响应在适应特定指令的同时，与核心身份保持一致
2. **闭环评判优化与对齐**
   在 RL 训练中，利用可验证信号优化 critic 模型：通过可验证奖励提示生成的 on-policy 轨迹，持续更新critic 模型。这一关键步骤将来自可验证奖励强化学习（RLVR）的客观性能信号直接融入 critic 模型，critic 对复杂且无明确奖励信号任务的主观判断建立在可验证数据基础上，让可验证任务的性能提升反哺评判能力。这种闭环流程确保评判体的评估标准随策略演化而同步调整，最终通过将主观评估锚定在可验证数据上，实现模型与复杂、不可验证人类目标的稳健且可扩展的对齐

![8.1.11 Kimi K2-image-7.png](https://2479e837.cloudflare-imgbed-2q4.pages.dev/file/1782697412927_8.1.11_Kimi_K2-image-7.png)

> **算法优化策略**
> * **预算控制（Budget Control）：** 为解决 RL 常导致生成内容过长、增加非推理领域推理成本的问题，在训练中为每个样本设置基于任务类型的最大 token 预算。超过预算的响应会被截断并施加惩罚，以激励模型在限定范围内生成简洁有效的解决方案，显著提升 token 效率
> * **PTX Loss：** 为避免联合 RL 训练中遗忘高质量数据，精选高优质样本数据集，通过辅助 PTX 损失将其融入 RL 目标。这一策略既利用了高质量数据的优势，又减轻了对训练集中有限任务的过拟合风险，提升模型在更广泛领域的泛化能力
> * **温度衰减：** 针对创意写作、复杂推理等任务，训练初期采用高采样温度促进探索，生成多样创新的响应以发现有效策略、避免过早收敛到次优解；后期通过温度衰减调度从探索转向利用，减少随机性，确保模型输出稳定且高质量
