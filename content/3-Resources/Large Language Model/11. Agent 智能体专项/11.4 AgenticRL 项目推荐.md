# Search 向 Agentic RL 篇

## RL for Search Agent 的总览

传统 RAG 更多是在固定的检索 pipeline 上做 prompt / reranker 优化，**模型本身并不会去学会如何搜索，什么时候进行搜索**。2025 年一些工作用 RL 训练 Search Agent，其大致有如下一些共同特征：

* **环境：** 从静态的知识库，到真实 Web 浏览器、垂直检索引擎
* **行为：** LLM 作为策略，决定 **何时搜索、搜什么、要不要继续搜索**
* **奖励：** 不只看 NDCG/BLEU 这类检索或生成指标，而是围绕任务完成质量 + 搜索成本去设计复合 reward
* **算法：** 多用 **PPO / GRPO 等 RLVR 算法的变体，支持长序列、工具调用和多步轨迹**

可以理解为在 LLM + 工具的基础上，把用好搜索工具变成大模型 RL 的学习目标

## 基础：Search-R1 生态和多跳 QA

### Search-R1

**论文：https://arxiv.org/pdf/2503.09516**

**Github：https://github.com/PeterGriffinJin/Search-R1**

* **Search-R1** 提出了一套完整的 RL 训练框架，让 LLM 在推理过程中交替发出搜索调用（本地检索或 Google/Bing）、阅读结果、继续思考，最后给出答案
* **场景：** NQ、TriviaQA、PopQA、HotpotQA、MuSiQue、2WikiMultiHopQA、等开放域 QA
* **核心设计：**
  * 轨迹是 **think + 搜索 action + 检索结果** 的交错序列
    示例：**`<think>思考过程</think><search>搜索用到的短query</search><information>检索回来的信息</information>`**
  * 用 **rule-based 结果型奖励判定答案正确性，并对搜索行为进行轻度奖励或约束**
  * 支持 PPO / GRPO / REINFORCE 多种算法

**大量后续工作都是在 Search-R1 的训练范式和代码上演化出来的**

### ReSearch

**论文：https://arxiv.org/pdf/2503.19470**

**Github：https://github.com/Agent-RL/ReCall/tree/re-search**

* **基本与 Search-R1 设计一致**
* RL：GRPO算法，**reward 主要基于模型答案和 ground truth 答案的 F1 score + 格式 / 结构约束奖励A**

### R1-Searcher/R1-Searcher++

**论文：https://arxiv.org/pdf/2503.05592v1，https://arxiv.org/pdf/2505.17005**

**Github：https://github.com/RUCAIBox/R1-Searcher，https://github.com/RUCAIBox/R1-Searcher-plus**

* R1-Searcher 整体 **与 Search-R1 设计一致，但是训练分成了两阶段**
  * **第一阶段：** 只训练检索动作，只给 **检索奖励+格式奖励**
  * **第二阶段：** 训练用搜到的东西正确回答问题，只给 **答案奖励+格式奖励**
* R1-Searcher++ 在前者基础上，**显式优化搜索效率**（减少无效调用），奖励中加入搜索调用数的标准差惩罚。即鼓励模型利用内部知识，并引入记忆机制将检索信息转化为内部知识，实现知识的动态积累与高效利用，提升推理效率

### StepSearch

**论文：https://arxiv.org/pdf/2503.19470**

**Github：https://github.com/Zillwang/StepSearch**

* StepSearch 认为 **只用全局终局奖励会导致多跳 QA 下的稀疏奖励问题**，因此提出 **step-wise PPO，** 每一次搜索调用都有中间奖励，基于信息增益和冗余惩罚计算
* 关键点：
  * 把 **推理过程拆成多个子问题**，每个子问题都有单独的搜索轨迹
  * **`奖励 = 答案正确性 + 每步检索到的关键信息增量 − 冗余度`**
  * 只用约 19k 训练样本就能在多跳 QA 上显著超越 Search-R1 / ReSearch

### AutoRefine

**论文：https://arxiv.org/pdf/2505.11277**

**GitHub：https://github.com/syr-cn/AutoRefine**

* 提出 **Search-and-Refine-During-Think** 范式，在连续的搜索调用之间插入 **显式知识精炼步骤**，并对检索质量给予额外奖励（除了答案奖励）

### AutoCoA

**论文：https://arxiv.org/pdf/2503.06580**

**Github：https://github.com/ADaM-BJTU/AutoCoA**

* 场景：多跳 QA + 开放 Web 混合，但训练环境仍以标准 QA 语料为主
* 设计：
  * 把 agent 拆成 **coarse-grained 课程和 fine-grained step**，通过 **层级 RL 学习先规划**，再查询和阅读
  * 冷启动阶段用模拟环境 / 合成轨迹，后面逐步转向真实环境
* RL：GRPO + curriculum

### R-Search

**论文：https://arxiv.org/pdf/2506.04185v1**

**Github：https://github.com/QingFei1/R-Search**

* 整体 **与 Search-R1 设计一致，多了<original_evidence></original_evidence> 在final answer中要求模型提供检索到的相关原始信息**
* 此外，设计了多类型的奖励：**答案奖励+证据奖励+格式奖励**

### DeepRAG

**论文：https://arxiv.org/pdf/2508.06165v3**

**Github：https://github.com/Tsinghua-dhy/UR2**

* 场景：多跳 QA + RAG
* 设计：
  * Reward 同时考虑 EM 和检索成本，逼着模型在准确和成本之间找到平衡
* RL：GRPO；Reward = Answer EM – λ \* Retrieval Cost

### s3

**论文：https://arxiv.org/pdf/2505.14146**

**Github：https://github.com/pat-jj/s3**

* s3 的主张是：**Search Agent 可以是一个独立组件**，不必和生成模型同一个 LLM
* 做法：
  * 冻结大模型生成，单独训练一个Searcher 模型
  * 奖励定义为 **Gain Beyond RAG**：相比 naive RAG，答案准确率提高了多少

### UR²

**论文：https://arxiv.org/pdf/2508.06165v3**

**Github：https://github.com/Tsinghua-dhy/UR2**

### O²-Searcher

**论文：https://arxiv.org/pdf/2505.16582**

**Github：https://github.com/KnowledgeXLab/O2-Searcher**

## 深度研究：从静态语料到真实 Web 环境

### DeepResearcher

**论文：https://arxiv.org/pdf/2504.03160**

**Github：https://github.com/GAIR-NLP/DeepResearcher**

* **DeepResearcher** 直接在真实 Web 环境上做 end-to-end RL，让 Agent 通过浏览器工具执行搜索、点击页面、阅读长文档，再综合多轮信息完成深度调研任务
* RL：GRPO，reward 为答案 F1 + 格式惩罚奖励

### WebSailor & WebSailor-V2

**论文：https://arxiv.org/abs/2507.02592，https://arxiv.org/pdf/2509.13305**

**GitHub：https://github.com/Alibaba-NLP/WebAgent，https://github.com/Alibaba-NLP/DeepResearch**

* **主要贡献：WebSailor** 针对 BrowseComp 风格的复杂信息检索基准，提出了一套完整的后训练方法和特殊的 RL 算法 **DUPO（Duplicating Sampling Policy Optimization）**
* 特点：
  * 通过“**不确定性驱动的任务采样**”构造高难度训练任务
  * RL 中不仅看最终答案，还考虑探索路径多样性、去重等因素

### DeepDive

**论文：https://arxiv.org/pdf/2509.10446**

**GitHub：https://github.com/THUDM/DeepDive**

* 设计：
  * 用公开知识图谱自动合成复杂、多跳、难以检索的问题
  * 在这类合成任务上进行 **multi-turn RL**，显著提升 open-source agent 在 BrowseComp 上的表现
* 亮点：把 **复杂任务合成 + 多轮 RL** 串起来

### ASearcher

**论文：https://arxiv.org/pdf/2508.07976**

**GitHub： https://github.com/inclusionAI/ASearcher**

* **ASearcher** 聚焦在turn>10 的超长搜索轨迹，提出完全异步的大规模 online RL 框架，可以支撑 40+次工具调用、上十万 token 输出的复杂 deep search

### SFR-DeepResearch

**论文：https://arxiv.org/pdf/2509.06283**

**GitHub：暂无**

* 场景：复杂 Deep Research，包括 Humanity’s Last Exam 等
* 设计：
  * 强调 **单 agent 自主决策**，而不是 workflow 里人为指定子 agent 角色
  * 强调 **只用 web search + browsing + Python interpreter 三种工具**
  * RL 用 **简单的 REINFORCE + LLM 评判**，但在 HLE 上做到 28.7%（文本-only），超过用 o3 + Kimi Researcher 等强商用 pipeline

### ASearcher

**论文：https://arxiv.org/pdf/2508.07976**

**GitHub：https://github.com/inclusionAI/ASearcher**

* **ASearcher** 聚焦在 **turn>10 的超长搜索轨迹**，提出完全异步的大规模 online RL 框架，可以支撑 40+ 次工具调用、上十万 token 输出的复杂 deep search
* 在 xBench、GAIA 上显著提升 Avg@4
* 单模型 QwQ-32B，在不开商用 API 的前提下逼近甚至超过一些闭源 search agent

### InfoFlow

***Reinforcing Search Agent via Reward Density Optimization***

**论文：https://arxiv.org/pdf/2510.26575v1**

**GitHub：https://github.com/VectorSpaceLab/Infomatica**

* 场景：深度搜索 + RLVR 设定
* 核心问题：深度搜索里 RLVR reward 极度稀疏，rollout 成本巨大
* 设计：
  * 把问题形式化为 **Reward Density Optimization**
  * 三个关键机制：
    * **Sub-goal Scaffolding：在搜索过程中插入可验证的子目标，提供密集进度奖励**
    * **Pathfinding Hints：利用离线优质轨迹给在线探索提供自适应引导**
    * **Trajectory Refinement：引入 refiner agent 对搜索轨迹压缩与重写，提高 reward 密度**

这个思路非常适合迁移到自己的复杂检索环境，只要可以构造局部可验证的 reward，就能把极长搜索任务也训练起来

### WebThinker

**论文：https://arxiv.org/pdf/2504.21776**

**GitHub：https://github.com/RUC-NLPIR/WebThinker**

* 场景：GPQA、GAIA、HLE、WebWalkerQA、SuperGPQA 等超高难度 benchmark。
* 设计：
  * 用 **DPO + PRM（过程 reward）优化多步 ReAct + 搜索 agent**，对工具调用次数和输出长度加惩罚
  * 更强调 search efficiency + long-horizon reasoning 的权衡
> 还可以看一下同作者的 [Search-O1](https://arxiv.org/abs/2501.05366)（偏早），以及较新的 [DeepAgent](https://arxiv.org/abs/2510.21618)

### ZeroSearch

**论文：https://arxiv.org/pdf/2505.04588v2**

**GitHub：https://github.com/Alibaba-NLP/ZeroSearch**

* ZeroSearch 直接用 LLM 本身来 **模拟搜索引擎**：先经 SFT 把 LLM 变成会生成既有用又有噪声文档的检索器，然后在这个虚拟环境里用 RL 训练 policy 学会发出好的搜索查询
* 优点：
  * 显著降低真实 API 成本（论文里提到约 88% 成本下降）

### SSRL：Self-Search RL

**论文：https://arxiv.org/pdf/2508.10874**

**GitHub：https://github.com/Alibaba-NLP/ZeroSearch**

* SSRL 完全不依赖外部搜索引擎，而是强化 LLM 的 **自搜索（Self-Search）** 能力：通过结构化 prompting 和多次采样，让模型在自己参数里的知识世界里搜索
* RL 奖励针对格式、规则遵守和知识利用有效性，最终这些 self-search policy 还能较好地迁移到真实搜索环境（sim-to-real）

## 拓展：多模态/垂直领域 Search Agent

### MMSearch-R1

**论文：https://arxiv.org/pdf/2506.20670v1**

**GitHub：https://github.com/EvolvingLMMs-Lab/multimodal-search-r1**

* **MMSearch-R1（Multimodal-Search-R1）** 把 Search-R1 的范式扩展到 MLLM：
  * 基座是 Qwen2.5-VL-7B，多模态（图像+文本）输入
  * 通过 GRPO 做 RL，让模型在多模态搜索工具上进行多轮交互
  * 主要在 FVQA 等视觉问答基准上验证

**Search RL 不局限于文本检索**，也可以用在看图 + 搜索 + 推理的场景

### VRAG-RL

**论文：https://arxiv.org/pdf/2505.22019**

**GitHub：https://github.com/Alibaba-NLP/VRAG**

* **VRAG-RL** 针对的是 **富视觉信息（图表、表单、文档截图）的 RAG**
  * 动作空间里除了搜索文本外，还有裁剪、缩放等视觉操作，让 VLM 能从粗到细收集信息
  * 奖励综合检索表现与模型评估奖励，强调视觉感知 token 的有效利用

**做图纸/图表类的检索 + 问答，VRAG-RL 的 action 设计和 reward 结构非常值得借鉴**

### WebWatcher

**论文：https://arxiv.org/pdf/2508.05748**

**GitHub：https://github.com/Alibaba-NLP/DeepResearch**

**WebWatcher** 进一步把 **Deep Research 做成多模态版本**：

* 支持在真实 Web 页面中同时处理图像、文本、布局信息
* 提出 BrowseComp-VL 基准，要求对视觉 + 文本混合信息进行复杂检索与推理
* 通过 RL 进一步强化视觉-语言深度搜索能力，在多个多模态 VQA/Deep Research 基准上超过开源 Agent 和 RAG workflow

### MedResearcher-R1

**论文：https://arxiv.org/pdf/2508.14880**

**GitHub：https://github.com/AQ-MedAI/MedResearcher-R1**

* 通过医疗知识图谱构造复杂多跳 QA 轨迹（KISA）
* 构建私有医疗检索引擎作为工具，配合通用工具一起使用
* 两阶段训练：SFT + 在线 RL，reward 综合医疗答案正确性、引用证据质量等指标
* 在 MedBrowseComp 等医疗基准上达成新 SOTA，同时保留不错的通用 deep research 能力

## 整合：如何做一个自己的 Agentic RL for Search 项目

### 纯 Search+RL 项目

* **项目目标：** 在 **静态文本语料上，做出一个会自己决定何时检索、如何改写 query 的 QA Agent**，并证明 RL 相比纯 RAG 有明显增益。可以整合 R1-Searcher、Search-R1、StepSearch等的优点
* **整合亮点：**
  * 借鉴 **Search-R1**：完整的 **Reasoning+Search 轨迹格式和 PPO/GRPO 训练流程，** 作为基础
  * 借鉴 **R1-Searcher**：**两阶段训练思路，先把会正确发起检索训好，再上答案奖励**
  * 借鉴 **StepSearch**：**步骤级奖励，对每次检索是否带来信息增益给中间 reward**
  * 奖励设计借鉴：可以 **整合多个项目的奖励设计，全都加在一起，顺便也能做消融实验**，丰富项目过程

### DeepResearch 项目

* **项目目标：** 做一个可控范围内的 Deep Research Agent，在小规模真实 Web 或模拟 Web 环境中，完成复杂信息汇总任务。整合 DeepResearcher、WebSailor、InfoFlow、ZeroSearch 等的优点
* **整合亮点：**
  * 借鉴 **DeepResearcher 和 WebSailor**：多步网页浏览，搜索、点链接、分页阅读、跨站对比；任务形式是写一段带引用的总结回答
  * 借鉴 **InfoFlow**： 使用 **子目标奖励和RLVR思路，提高 reward 密度**
  * 借鉴 **ZeroSearch 和 SSRL**： 先在 **模拟搜索环境里训练策略，再迁移到真实 Web，控制成** 本

### 垂直领域多模态 Search+RL 项目

* **项目目标：** 在一个 **具体垂直领域做图文混合的检索+推理 Agent，例如科研论文图文理解、金融报告图表问答、或医学文档+图像解释**。整合 MMSearch-R1、VRAG-RL、WebWatcher 的优点
* **整合亮点：**
  * 借鉴 **MMSearch-R1**：多模态输入，问题可以涉及文本和图片内容，例如“图2中的趋势和正文结论是否一致”；搜索动作既可以检索文本段落，也可以检索相似图像
  * 借鉴 **VRAG-RL**：视觉操作动作，比如裁剪某块图像、放大特定区域、只读取图表标题等
  * 借鉴 **WebWatcher**：多页 PDF 环境，Agent 要在多页文档之间跳转找到关键信息
